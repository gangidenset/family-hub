# 01. 要件整理

## 1. 製品コンセプト

**FamilyHub** — 家族の買い物リスト・メモ・予定・タスクを、**サーバーに預けずに**家族のスマートフォン間で共有するアプリ。

| 価値 | 具体的な約束 |
|---|---|
| オフラインで快適 | 機内モードでも全ての閲覧・登録・編集ができる |
| 家族で簡単に共有 | QR コードを読み取るだけで家族に参加・同期できる |
| 個人情報を守る | アカウント不要。データは家族の端末にだけ存在し、開発者を含む第三者のサーバーには一切送られない |
| 誰でも使える | 主要操作は 3 タップ以内。大きなボタン、読みやすい文字 |
| 買い切り | 広告・月額・トラッキングなし |

## 2. 対象ユーザー・利用シーン

- 2〜6 人程度の家族（夫婦・子ども・同居の祖父母）
- 主なシーン: スーパーでの買い物リスト確認、週末の予定共有、家事分担、学校プリント内容のメモ
- 技術リテラシーは様々（高齢者・子どもも想定）

## 3. 機能要件（初期版スコープ）

| ID | 機能 | 主な要件 | Phase |
|---|---|---|---|
| F-SHOP | 買い物リスト | 複数リスト / 追加・編集・削除 / 購入済みチェック / カテゴリー / 数量 / メモ / 並び替え / 購入履歴 | 2 |
| F-MEMO | 共有メモ | タイトル・本文 / カテゴリー / ピン留め / 更新日時表示 | 2 |
| F-CAL | 予定管理 | 登録・編集・削除 / 日時・終日 / 参加メンバー / カテゴリー / 月表示カレンダー | 2 |
| F-TASK | タスク管理 | 担当者 / 期限 / 完了チェック / 未完了一覧 | 2 |
| F-HOME | ホーム | 各機能への導線 / 未完了タスク / 直近の予定 / 同期状態 | 2 |
| F-MEMBER | 家族メンバー | 家族グループ作成 / メンバー（人）と端末の追加・削除 | 2〜3 |
| F-SYNC | 端末間同期 | QR ペアリング / 同一 Wi-Fi での P2P 同期 / 競合処理 / 再試行 / 状態表示 | 3 |
| F-BACKUP | バックアップ | JSON 出力 / 復元（検証＋確認画面）/ 全削除 / データ形式バージョン | 4（基礎は 2） |
| F-SET | 設定 | ライト/ダーク/自動 / 文字サイズ / 言語（日本語先行） | 2 |

### スコープ外（初期版では実装しない／将来検討）

- 予定の繰り返し・リマインダー通知（PWA の通知はバックグラウンド制約が大きいため、ネイティブ化時に検討）
- 画像添付（データ量・同期負荷が大きい）
- インターネット越しの遠隔同期（サーバーなしでは NAT 越えが原則不可能。[06-sync-design](./06-sync-design.md) 参照）
- 決済機能（ストアの有料アプリとして販売するため、アプリ内決済は不要の想定）

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| オフライン | 初回読み込み後はネットワークなしで起動・全機能動作。Service Worker で全アセットをプリキャッシュ |
| データ保存 | IndexedDB。`navigator.storage.persist()` を要求し、ブラウザによる自動削除を抑制 |
| 性能 | 起動 2 秒以内（中級 Android 端末想定）/ 操作応答 100ms 以内 / 1 グループ 1 万レコードで快適に動作 |
| 対応環境 | iOS 16.4+ Safari（ホーム画面追加）/ Android 10+ Chrome。PC ブラウザは参考対応 |
| プライバシー | 外部通信ゼロ（アプリ配信元からの更新取得を除く）。解析・広告 SDK なし。外部フォント・CDN 不使用 |
| セキュリティ | [07-security](./07-security.md) 参照 |
| アクセシビリティ | タップ領域 48×48px 以上 / コントラスト WCAG AA / OS 文字サイズ追従 / スクリーンリーダーのラベル |
| 保守性 | TypeScript strict / 機能単位のモジュール分割 / 単体・E2E テスト |
| 将来性 | Capacitor でネイティブアプリ化（ストア配布）できる構成 |

## 5. 前提・制約（正直に明記すべき事項）

1. **バックグラウンド同期はできない**: PWA は閉じている間に通信できない。同期は「両方の端末でアプリを開いているとき」に行う。
2. **サーバーなしの P2P 接続には毎回 QR 交換が必要**: ブラウザの WebRTC は接続ごとに接続情報が変わるため、同期のたびに 2 回の QR 読み取り（約 10〜20 秒）が必要。詳細と代替手段は [06-sync-design](./06-sync-design.md)。
3. **Wi-Fi 環境によっては P2P 接続できない**: ゲスト Wi-Fi や AP 分離が有効なルーター、マルチキャスト遮断環境では接続不可。その場合は暗号化ファイルでの同期に切り替える。
4. **メンバー削除で既に渡したデータは取り消せない**: 削除後の新しい更新を渡さないことは保証できるが、相手端末に既にあるデータの消去は保証できない（サーバーレス設計の本質的制約）。
5. **端末紛失時**: データは各端末にあるため、家族の他の端末から復元できる。全端末を失った場合はバックアップファイルからのみ復元可能。
